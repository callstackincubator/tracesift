Cut the noise out of the task hand-off so more of it is something an agent can act on.

Stack frames inside a bundle are named by their chunk and position — `vendors.bundle.js:189:701931` — instead of the full URL. The origin repeats on every line of every stack and the content hash changes with each build, so neither separates one frame from another; a path a developer can actually open is still printed whole. This applies to the stacks Explore draws as well.

A frame whose hot path is only itself now says "It recurses into itself." on its row, in place of a block repeating the same line seven times. Each culprit row carries the callers that locate it — `Called via reportMatchesTodoBucket › isApproveAction › isScanning` — which is the most searchable thing on the row for an agent holding the codebase, and what tells two frames sharing a minified name apart. The per-culprit stacks are replaced by one merged tree covering every listed culprit.

An inference is no longer truncated to fit the card. Cutting a finding to 220 characters removed exactly the call site, offset or count that earned it.

Three sections the receiving agent cannot act on are gone. "Named work inside the task" repeated subtree names already in the rows below it. "The task" no longer restates the offset into the recording or how the boundary was decided — that is on the card the developer copied from. The task's duration survives only as the denominator its boundary frames divide. "How to read these numbers" keeps only the caveat that changes what the agent does: nothing here opened a source file.

"Stacks" becomes "Where those frames sit": one tree joining the task root to every culprit, instead of a separate stack for the top two or three. Separate stacks repeat each other — the culprits under one React render share the dozen frames above them — so ten of them are mostly ten copies of one chain, and the fact worth reading, that these costs are siblings under a single render, is the first thing that repetition buries. Merged, the shared chain is drawn once, the branch points are visible, and every culprit in the list is reachable in roughly the space three separate stacks used to take. Runs of frames carrying no name worth reading fold into one line, and the line says what they were — `… (5 framework frames)`, `… (3 engine frames)` — so a reader can tell "that is all React" from "the frame I need is in there". A frame with a name a developer can act on is never folded, whether the classifier filed it under `app` or, as a bundled build routinely does with the product's own screens, under `library`.

The hand-off accounts for the task instead of a corner of it. The culprit list was floored at 2% of the task, and a share of the block means the longer the task, the less of it the hand-off explains: on a 3.2 s task it cut at 64 ms, named five frames covering 24% of the duration, and left 2.4 seconds to a single remainder line — so the agent could not tell whether the fix was in the five frames it saw or in the 76% it did not. The floor is now `CULPRIT_MIN_MS`, the absolute cut the card already admits a culprit on, and up to 25 rows are listed against the 12 before. Where the remainder goes is a measurement too: it says how many more frames ranked below the list and how large the largest of them is, because "spread thin" and "there are forty rows you were not shown" are different situations and the line used to read the same either way.

"The task" lists its boundary frames with their numbers rather than as a bare row of names. Those frames are an antichain — the search for them stops at the first product frame on each branch — so none nests inside another, their inclusive times are disjoint, and they divide the task between them. That makes it the one section whose figures account for the whole block, which matters most on exactly the profiles where self time is dust spread over thousands of frames. A frame admitted on inclusive time alone now appears only there: listed among the culprits it read `0 ms of its own time`, which is a row about nothing.

A frame's position is shown where it locates the frame and dropped where it does not, in the hand-off and in the UI alike. The rule was readable paths only, which on a minified profile left every culprit row and every tree label with no position at all; printing them all instead put a chunk and an offset on forty rows, and on most of those the name was already the better key — an agent holding the codebase greps `getReportSections`, and `8339.bundle.js:1:92293` cannot be opened, says nothing a name search would not, and is different after the next build. In a card row it was worse than useless, because the row labels it `file`. So a source path is shown whole, and a build artefact is shown only where the name does not stand on its own: a name that says nothing by itself — `(anonymous)`, `t.A`, `l` — or a name the profile recorded at more than one position. That last case is why the rule is not a test on the URL: a bundle routinely leaves two different `compute` functions sharing a name and a caller chain, and without their offsets those are two identical rows for two different functions. Ambiguity is judged across a whole card, so a frame reads the same in the hand-off, the culprit table, the card and the tree. When a chunk offset is shown in a hand-off at all, the caveats say what it is, so the receiving agent does not go looking for a file that does not exist.

Fixed along the way: a compacted chunk label could pass as a source file. `isReadableSourcePath` is given whole URLs, and its scheme test needs a letter first — so `main.bundle.js:91:1` was rejected only by accidentally looking like a scheme, and `8339.bundle.js:1:92293`, which is what code splitting actually emits, was accepted as a path a developer could open. Two callers were asking it about compacted labels, one of them the stack compaction whose whole rule is never to present a URL as a source file.

The hand-off opens with what it is for: investigate the root cause of this bottleneck in the code named below, from evidence that says where the time went and not why. Opening on `## The task` read as a report, and a report invites a summary back.
