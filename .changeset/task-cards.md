Rebuild CPU analysis around tasks, so every headline number is wall-clock time you can scrub to.

The call-tree engine this replaces picked one node out of a profile-wide merged tree and called it a card, and three things about that were wrong structurally rather than by tuning. Its numbers were not wall clock: the tree merged every invocation of a frame under one parent path, so `runCompute spent 424 ms` was fifty scattered calls summed, there was no point on the timeline to check it against, and one 424 ms call rendered identically to five hundred calls of 0.8 ms although the fixes for those are opposites. Its ranking was incoherent, because cards were ranked by inclusive time over nodes that nest, so the same millisecond was claimed by several cards and the card totals could exceed the recording many times over. And its descent optimised for the wrong frame: it required a node to keep a quarter of its own subtree, so `Search_Search` — the point where React hands off to product code, and the frame a human points at — was walked straight past for delegating everything downward.

The unit of a card is now a task. Chrome records them as `RunTask` events, Hermes duration traces have one per top-level call, and a trace carrying neither falls back to splitting sample runs on idle gaps and says in the card, the prompt and the Explore header that those boundaries were inferred rather than measured. Tasks do not overlap, so their shares add up to at most a hundred percent, self time inside one is a true partition where every millisecond belongs to exactly one frame, and a card's duration is a block of time that really did pass. A card names the task, subtitles it with the outermost drawable frames on its stacks — which feature this is, a lookup rather than a heuristic descent — and lists the frames that burned the time, each with the shape of how it burned it: `ran 54 times in this task · 424 ms total · longest single call 11 ms`. That line is the one that tells you whether you are looking at an algorithm or at a call site, and no inclusive total can.

Deciding which frames are the product's own is now its own table. The URL settles it whenever a profile carries real paths; the existing framework and runtime name lists sit underneath that; and only what neither resolved — which, in a React Native bundle where every frame shares one URL, is most of the interesting names — goes to a model, once per upload and over distinct names rather than samples. The answers are cached by name and URL and persisted, so a second profile of the same app is a lookup and re-running one file cannot quietly produce different findings. If no model is available the upload still succeeds on the rules alone and the analysis says it was degraded.

A garbage collection pause does not end the call it interrupts. V8 parks `(garbage collector)` at the root of the stack rather than under the frame that allocated, so to anything reading samples in order it looks exactly like the whole JS stack returning and a new one starting. Counted that way, one 290 ms render that collected eleven times reported as thirteen calls of 85 ms or less — a call site to look at rather than an algorithm, which is the opposite of the finding, and a number that contradicted the flame chart a reader was holding it against. Those samples are now carried across rather than treated as a return, and are still not credited to the interrupted frame, so the shapes keep summing to the totals the call tree reports.

Explore draws the task against the clock, with React and the engine collapsed away. Every other view in this tool reads the merged call tree, where the horizontal axis means nothing and fourteen separate renders spread over three seconds are one wide box; a reader holding a card against Chrome's Performance panel could not line the two up, because the two pictures answer different questions. The new view keeps the axis. A box is one call at the position it ran, built from the same sample sequence the invocation shapes are counted on, so a frame the card says ran three times has three boxes — and collapsing the reconciler and the scheduler lifts a component that really sat twelve deep onto the first row, where the wall of `flushSyncWorkAcrossRoots_impl`, `beginWork` and `commitPassiveMountOnFiber` used to be.

What the chart keeps is your code and your dependencies together, and what it drops is React and the engine. Keeping the product's own frames alone assumed the classifier could tell the two apart, and in a bundle it frequently cannot: on a webpack build every URL is a hashed chunk, so the rules resolve nothing, the residue that reaches the model is capped, and the fallback for everything else is `library`. On a real three-second task of a bundled app that drew an empty chart over work that was entirely the reader's own. Drawing both makes the judgement cosmetic — a frame misread as a dependency is still on the chart, in the right place, at the right width — and the same widening gives a card its captions, which previously went missing on exactly those profiles. V8's `Function call` wrappers are kept too, rather than filed with the engine built-ins for carrying no URL: they are where a call began, and dropping them broke the nesting around the frames underneath.

What is collapsed is reported rather than hidden: the stretches where only React or engine code was on the stack are left as gaps on a hatched ground and counted in the legend, because a task that is two seconds of product code and one of framework is a finding, and filling those gaps in would bury it. Resolution is the sampling interval, and a box's span is wall clock, so it covers the framework work the call delegated to and any collection pause inside it — which the view says, since the card's longest-call figure counts neither and the two numbers would otherwise look contradictory.

Explore now opens one task. It fetches the task from the server rather than being handed it through `sessionStorage`, which could not carry one: a task card ships its call tree whole and that runs to several megabytes on a long task, past what an origin is allowed to store. The write threw, the throw was swallowed so that a click would never fail outright, and the tab opened empty — on exactly the longest tasks, which are the ones worth opening. It receives the whole subtree — no depth or breadth truncation, because the payload is bounded by the task rather than by the recording — and opens focused on the frame you clicked, with the frames above it folded into a breadcrumb that expands and the frames beside it one click away. Rooting that view at the top of a task would show a wall of scheduler and reconciler frames before any product code appeared, and a view holding only the focused subtree could never answer how you got there or what else ran alongside, which is the second question every time. The copy hand-off is rebuilt on the same measurements and stays evidence rather than conclusion: it has frame names, positions and timings and has read no source file, and a guessed root cause would only anchor the receiving agent on this tool's inference instead of its own reading of the code.

The two engines this replaces both stay. `TRACESIFT_CPU_ENGINE=cards` serves the node-descent cards and `=legacy` the original grouping and its analyst agent, so a profile whose task cards look wrong can be run through all three and compared.
