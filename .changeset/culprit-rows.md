Give a task card's rows to the functions that burned the time, not the ones that delegated it.

The rows were the boundary frames — the outermost drawable frame on each branch — ranked by inclusive time. That is the wrong end of the stack to put a bar against. A boundary frame is by construction the frame furthest from the work, so on a React profile it is a component that hands everything downward: on a real 3.2 s task six of the eight rows read `0 ms self`, their bars measured how long the frame sat on the stack rather than what it cost, and two cards over the same screen listed the same five names, so the page could not say which of them to open. Which feature ran is worth saying once, and the heading already said it.

The rows are now the culprits, ranked by effective self time, which is a true partition of the task: the figures add up and no millisecond is claimed twice. Each carries the shape it was already measured with — `ran 125 times in this task · 140 ms total · longest single call 4 ms` — and, new here, the named callers that reached it. A function name on its own is rarely a finding: `isReceiptBeingScanned` could be anything, and `isReceiptBeingScanned, via reportMatchesTodoBucket › isApproveAction › isScanning` is a per-item predicate inside a filter, which is a thing to go and change. The existing `reachedVia` could not be reused for that line — it starts at the root and carries each frame's URL and column for the hand-off, which on a bundled app is several hundred characters of hashed chunk name per row — so a card now carries the nearest three named callers, names only, with framework, engine, anonymous and mangled frames dropped.

The boundary frames move to the subtitle, starting after the two the heading already names, so a task entered through a single frame has no second line rather than one echoing its title. That replaces `8 entry points into your code in this task`, which counted the rows beneath it and said nothing else.

The footnote now says what the remainder is shaped like rather than only how big it is. A five-row list covering a quarter of a three-second task reads as a short measurement unless the card says the cost really is spread that thin — that task has 1242 distinct frames with self time, its top five hold 25% and its top forty 60%, and nothing in it is a hot function. That is the finding, and it is the opposite of a 219 ms task whose top five hold 53%. A task now carries up to 24 culprits, everything holding at least 15 ms of its own time or 15 ms including its callees, and a card shows the first eight of them while Explore's Culprits tab holds the whole list to sort and scan. At a three percent floor the tab had five rows on that three-second task and one on a 2.3 s devtools profile, which is not a table. A task where nothing clears the floor falls back to the boundary frames rather than rendering a card with no rows, which would have taken the footnotes with them.
